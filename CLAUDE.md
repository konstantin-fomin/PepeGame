# PepeIdle — AI Developer Guide

> Ты AI-разработчик проекта **PepeIdle**. Читай этот файл полностью при каждом запуске сессии.

---

## 0. Навигация и эффективность

### Чтение файлов
- Используй Grep для поиска нужного места **до** открытия файла
- Читай точечно с диапазоном строк (`offset` + `limit`), не целиком
- Не перечитывай файлы, которые уже были в контексте этой сессии

### Стиль ответов
- Без преамбул ("Конечно!", "Отличный вопрос!") — сразу к делу
- При мелких правках — только изменённый фрагмент, не весь файл
- Связанные правки в одном файле — один вызов Edit, не несколько
- **Любые правки кода — только полными файлами** (требование проекта)
- **Имена файлов и классов фиксированы** — не переименовывать

### Что игнорировать (см. `.claudeignore`)
- `Library/` — кэш Unity (гигабайты, бинарники)
- `Temp/` — временные файлы сборки
- `obj/` — скомпилированные объекты
- `Logs/` — логи редактора
- `.vs/` — Visual Studio кэш

### Быстрый старт задачи
```bash
# Найти класс:        Grep "ClassName" Assets/Scripts/
# Открыть скрипт:    Read Assets/Scripts/Core/GameManager.cs
# Структура данных:  Read Assets/Scripts/Data/
# Запустить игру:    /launch
```

## 1. Игра — PROJECT_CONTEXT

**PepeIdle** — 2D Idle / Clicker, PC desktop (мобильная версия TBD).
Unity (2D, URP). Целевая аудитория: IT-специалисты и офисные сотрудники 20–40 лет.
Тон: жёсткий офисный сарказм, ирония, выгорание.

### Основной игровой цикл
Игрок кликает по рабочей зоне → зарабатывает **KPI** → покупает карточки апгрейдов в трёх ветках (Click / Passive / Special). Пассивный доход генерирует KPI со временем. Параллельно накапливается **Experience (XP)** — только для прогрессии рангов: **Intern → Junior → Middle → Senior → Lead → CEO**.

### Экономика
**KPI:**
- Основная валюта, тратится на апгрейды
- Зарабатывается кликами и пассивом
- Никогда не уходит в минус, верхний лимит отсутствует

**Experience (XP):**
- Только для прогрессии рангов, не тратится
- Не накапливается после CEO
- **KPI и XP никогда не смешиваются**

### Апгрейды / Карточки
- 3 постоянных слота: Click / Passive / Special
- Для каждого ранга — собственные ветки апгрейдов, строго по порядку
- Возврат к предыдущему апгрейду невозможен
- Special: один активный, блокируется на время действия, после окончания заменяется следующим

### Оффлайн-прогресс
- Расчёт по UTC timestamp delta
- Без ограничения по времени оффлайна
- Полностью идентичен онлайн-прогрессу, учитывает все модификаторы

### Save / Load
- Один слот сохранения
- Автосейв при паузе и выходе
- Хранит: KPI, kpiPerClick, kpiPerSecond, Experience, ранг, индексы веток, активные Special + оставшееся время, UTC timestamp последнего сохранения
- Повреждённый сейв: логируется, сбрасывается с начала
- Reset — только для тестирования, не игровая механика

## 2. Дизайн — DESIGN_CONTEXT

**Платформа:** Mobile (portrait) + PC. Короткие частые сессии.

**Тема:** Офис / IT. Сарказм, выгорание, рутина, абсурд. Юмор сухой и сдержанный.

**Фантазия игрока:** офисный сотрудник поднимается по карьерной лестнице.

**Ограничения дизайна:**
- KPI никогда не уходит в минус
- Нет принудительного ожидания
- Reset только для тестирования
- Prestige запланирован в будущем, сейчас не активен

**Не зафиксировано:**
- Финальный баланс экономики
- Механика Prestige
- Долгосрочные системы удержания

## 3. Тексты — TEXT_CONTEXT

**Язык:** Русский. Разговорный, без тяжёлого сленга. IT/офисная лексика — допустима.

**Тон:** Сухой офисный сарказм. Тихое отчаяние. Абсурд как норма. Юмор сдержанный.

**Стилевые правила:**
- Короткие фразы, простые конструкции
- Нейтральный или пассивный тон
- Звучит как внутренний корпоративный текст
- «Уставший, но функциональный»

**Карточки:** Заголовок — короткий, нейтральный или ироничный. Описание — одно короткое предложение, без восклицательных знаков, без риторических вопросов.

**Примеры хорошего тона:**
> «Работает. Не спрашивай как.»
> «Лучше не трогать.»
> «Временно. Уже навсегда.»
> «Так принято.»

**Запрещено:** мотивационный тон, эмоциональный текст, громкий юмор, emoji, мат, мемы.

## 4. Арт — ART_CONTEXT

**Стиль:** Pixel art 16/32-bit. Минимализм, ограниченная палитра (6–10 цветов на иконку). Без реализма, 3D, неона.

**Иконки:**
- PNG, 512×512, прозрачный фон
- Один объект, центрированная композиция
- Объект занимает ~70–80% площади иконки
- Без текста, рамок, UI-элементов, фоновых объектов
- Читаемость силуэта — приоритет над деталями

**Карточные фоны:**
- PNG 1024×1536, непрозрачные
- Цвет фона = ветка (Click / Passive / Special)

**Запрещено:** реалистичный рендер, элементы вне рамки иконки, декоративные детали без смысла.

## 7. Архитектурные правила

**Запрещено:**
- Бизнес-логика в UI-кнопках
- Switch/if по конкретным рангам и апгрейдам
- Смешение KPI и Experience
- Статические поля состояния
- Временные решения
- Изменение ScriptableObject в рантайме

**Обязательно:**
- Строгое разделение логики и UI
- Data-driven архитектура
- ScriptableObject не изменяются в рантайме — все значения кэшируются в runtime-структуры
- Менеджеры существуют в сцене
- UI обновляется по событиям, не по polling
- Один класс — одна ответственность

**GameManager:** Singleton, оркестратор систем, не хранит экономику напрямую.
**UIController:** управляет только отображением.
**WorkZone:** UI блокирует клики по WorkZone.

- Имена файлов и классов фиксированы — не переименовывать
