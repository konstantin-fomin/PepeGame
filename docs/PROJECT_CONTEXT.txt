PROJECT OVERVIEW
Жанр: 2D Idle / Clicker
Платформа: PC (desktop). Мобильная версия — отдельная сборка (TBD)
Движок: Unity (2D, без URP)
Целевая аудитория: IT-специалисты и офисные сотрудники 20–40 лет
Тон: жёсткий офисный сарказм, ирония, выгорание

Основной игровой цикл:
Игрок кликает по рабочей зоне, зарабатывая валюту KPI, и покупает карточки апгрейдов в трёх ветках (Click / Passive / Special).
Пассивный доход генерирует KPI со временем.
Параллельно накапливается Experience (XP), которая используется исключительно для продвижения по рангам:
Intern → Junior → Middle → Senior → Lead → CEO.
Карточки и их ветки зависят от текущего ранга.
Поддерживается оффлайн-прогресс и сохранения.

ARCHITECTURE RULES
Принципы:
- Строгое разделение логики и UI
- Data-driven архитектура
- Один шаг разработки = один результат

Ограничения:
- Любые правки кода — только полными файлами
- Имена файлов и классов фиксированы
- Временные решения не допускаются

Запрещено:
- Бизнес-логика в UI-кнопках
- Switch / if по конкретным рангам и апгрейдам
- Смешение KPI и Experience

GAME SYSTEMS
Экономика:
KPI:
- Основная валюта
- Тратится на апгрейды
- Зарабатывается кликами и пассивом
- Никогда не уходит в минус
- Верхний лимит отсутствует

Experience (XP):
- Используется только для прогрессии рангов
- Не тратится
- Не уходит в минус
- Не накапливается после достижения максимального ранга (CEO)

Прогрессия:
- Ранги: Intern → Junior → Middle → Senior → Lead → CEO
- Новый сейв всегда начинается с Intern
- Пропуск рангов невозможен
- Откат рангов возможен только через будущую механику prestige (не реализована, планируется)

Карточки / Апгрейды:
- 3 постоянных слота: Click / Passive / Special
- Для каждого ранга — собственные ветки апгрейдов
- Апгрейды идут строго по порядку
- Возврат к предыдущему апгрейду невозможен
- Купленные апгрейды предыдущих рангов сохраняются

Special:
- В одном слоте может быть активен только один Special
- Повторная активация до окончания таймера невозможна
- На время действия карточка блокируется
- После окончания таймера карточка исчезает и заменяется следующей

OFFLINE PROGRESS
- Рассчитывается по разнице времени (UTC timestamp delta)
- Начисляется без ограничения по времени
- Максимального оффлайн-времени нет
- Расчёт полностью идентичен онлайн-прогрессу
- Учитывает все активные модификаторы и Special-эффекты
- Влияет на KPI и Experience
- Защита от абьюза через смену системного времени — TBD

SAVE / LOAD
- Один слот сохранения
- Автосейв при паузе и выходе
- Хранится:
  KPI, kpiPerClick, kpiPerSecond
  Experience
  Текущий ранг
  Индексы веток апгрейдов
  Активные Special и оставшееся время
  Время последнего сохранения (UTC)

Reset:
- UI-кнопка, предназначенная исключительно для тестирования
- Полностью сбрасывает игровой прогресс
- Никогда не используется как игровая механика в релизной версии

Повреждённый или несовместимый сейв:
- Логируется
- Сбрасывается с началом новой игры

Миграция сейвов между версиями — TBD

DATA & CONFIGURATION
ScriptableObject:
- RankData
- SlotBranchConfig
- Upgrade

Runtime:
- SlotBranch

Правила:
- ScriptableObject не изменяются в рантайме
- Все значения кэшируются в runtime-структуры
- Порядок апгрейдов в конфиге — единственный источник истины

Импорт данных:
- CSV / JSON используется как editor-time tooling
- Импорт полностью заменяет данные конфигов
- Импорт не используется в рантайме
- Редактирование конфигов без пересборки билда не допускается

UI / UX
- Canvas фиксирован
- UIController управляет отображением
- UI не содержит бизнес-логики
- UI блокирует клики по WorkZone
- Поддержка мыши и тач-инпута
- UI обновляется по событиям
- Карточки имеют состояния: active / disabled / locked
- Визуальный фидбек: всплывающий +X KPI при клике

ART & STYLE
- Pixel art 16/32-bit
- Минимализм, ограниченная палитра
- Без реализма и 3D

Карточки:
Фоны:
- 1024×1536 PNG
- Непрозрачные
- Цвет фона = ветка (Click / Passive / Special)

Иконки:
- 512×512 PNG
- Прозрачный фон
- Один объект
- Без неона

CODE STYLE
- Один класс — одна ответственность
- Singleton для GameManager допускается
- Статические поля состояния не используются
- Менеджеры существуют в сцене
- Ограничение классов — по ответственности
- Unit-тесты вне Unity — TBD

WORKFLOW WITH AI
- Отдельные чаты: CORE / ART / TEXT / BALANCE / CODE
- Пользователь может присылать текущие версии файлов
- ChatGPT может предлагать новые файлы
- Перед правкой файла всегда ожидается его текущая версия
- Временный код для отладки — нежелателен, но допустим
- Ведение changelog допустимо
